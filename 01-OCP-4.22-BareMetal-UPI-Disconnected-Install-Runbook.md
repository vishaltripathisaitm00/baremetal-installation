## 1. Solution Overview

**Install method — pure UPI, every node the same way:**
1. Boot the node from the RHCOS **live ISO** via iDRAC virtual media.
2. On the live shell, set the hostname and configure networking (bonded NICs + tagged VLAN) with `nmcli`/`nmtui`.
3. Wipe the local disk.
4. Run `coreos-installer install` pointing at the RHCOS raw image and the role-appropriate `.ign` file, both served by the bastion's `httpd`.
5. Reboot into the freshly installed node.

**Order of operations:** bootstrap → 3 masters (parallel is fine) → `wait-for bootstrap-complete` → decommission bootstrap → 6 CPU workers + 2 GPU workers (parallel is fine) → approve CSRs → `wait-for install-complete`.

**Load balancing:** AVI (NSX ALB) is external to the cluster. DNS `api`/`api-int` resolve to the AVI API Virtual Service IP (pooled to masters + bootstrap during install, masters only afterward, ports 6443/22623). DNS `*.apps` resolves to the AVI Ingress Virtual Service IP (pooled to the workers running the router, ports 80/443). Because an external LB handles this, `install-config.yaml` uses **`platform: none`** — there is no `apiVIPs`/`ingressVIPs` block and nothing for the cluster to self-manage.

```
                         ┌───────────────────────────────────────────┐
                         │   Bastion + Mirror Registry (combined)    │
                         │   httpd, openshift-install, oc, coreos-   │
                         │   installer, registry:8443, open proxy    │
                         └───────────────┬─────────────────────────┘
                                          │ 10.57.33.0/25 (VLAN 267)
                    ┌─────────────────────┴─────────────────────┐
                    │        AVI (NSX ALB) Virtual Services      │
                    │  api  VS  :6443/:22623 → masters (+bootstrap│
                    │             during install only)           │
                    │  apps VS  :80/:443     → all workers        │
                    └─────────────────────┬─────────────────────┘
        ┌──────────┬──────────┬──────────┼──────────┬──────────┬──────────┬──────────┐
   bootstrap    master1    master2    master3    worker1..6            gpu-worker1/2
   (temp VM     RHCOS live  RHCOS live RHCOS live  RHCOS live ISO       RHCOS live ISO
   on bastion)  ISO+CI      ISO+CI     ISO+CI      + coreos-installer   + coreos-installer
                                                    (worker.ign)         (worker.ign, GPU
                                                                         enablement = Doc 2)
```

### 4.1 Virtual Services and Pools required

| Virtual Service | VS IP | Port(s) | Pool members **during install** | Pool members **after bootstrap removal** | Health monitor |
|---|---|---|---|---|---|
| `vs-a1procpait01-api` | `10.57.33.6` | `6443` (TCP passthrough) | bootstrap + master1/2/3 | master1/2/3 only | TCP `6443` |
| `vs-a1procpait01-mcs` | `10.57.33.6` | `22623` (TCP passthrough) | bootstrap + master1/2/3 | master1/2/3 only | TCP `22623` |

**Critical settings:** L4/TCP pass-through only on all three VSes (OpenShift's API server and router terminate their own TLS); Round Robin or Least Connections; no AVI-side persistence on 443 (the router does its own cookie affinity at L7).

> **Remember to remove the bootstrap node from the `api`/`mcs` pools once bootstrap is decommissioned (Section 10)** — a stale, powered-off pool member doesn't break anything (AVI's health monitor will just mark it down), but clean it up as part of the cutover so on-call staff aren't confused by a permanently-down pool member later.

## 15. Troubleshooting Matrix

| Symptom | Likely cause | Fix |
|---|---|---|
| `WARNING imageContentSources is deprecated` | Old field name | Use `imageDigestSources` (Section 6.2) |
| `wait-for bootstrap-complete` hangs | DNS `api-int` not resolving, AVI pool doesn't include bootstrap yet, or NTP skew | Re-check Section 3.2/4.1/3.3; `ssh core@bootstrap "journalctl -b -f -u bootkube.service"` |
| A master/worker never appears on network after ISO boot | `nmtui`/`nmcli` step skipped or wrong NIC names | Re-check Section 9.2; confirm real interface names via `nmcli device status` before configuring |
| `coreos-installer` fails to fetch ignition | httpd not serving, wrong `--ignition-url`, or firewall blocking bastion:80 | `curl -I http://10.57.33.26/ai/<role>.ign` from the node's live shell |
| CSR stuck Pending | Approval step skipped, or second (serving) round not yet issued | Re-run the `oc adm certificate approve` one-liner in 11.1; wait and check again |
| `image-registry` ClusterOperator Degraded | No storage backend (expected on bare metal) | Configure PVC/ODF/NFS storage (13.4) |
| GPU node shows no PCI NVIDIA device | BIOS setting (SR-IOV/Above 4G decoding) not enabled, or card not seated | Re-check Section 3.1 BIOS checklist; reseat/verify in iDRAC hardware inventory |
| Node installed but wrong hostname/IP | `hostnamectl`/`nmcli` typo, or ignition file for wrong role used | Reboot to live ISO, re-run 9.2/9.3 for that node with correct role's `.ign` |
